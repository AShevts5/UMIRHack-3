# OCR-бенчмарк открытого набора

Метрики качества распознавания, отдельно от метрик извлечения полей. Определения
взяты из бенчмарка проекта `PdfOcrDesktop`
(`Desktop/projects/pdf/scripts/benchmark_ocr.py`), чтобы числа двух проектов были
сопоставимы.

## Что измеряется

| Метрика | Определение |
|---|---|
| `char_accuracy` | `1 − CER` по склеенному тексту страницы; обе стороны нормализуются так же, как в `evaluate.py`: NFC, регистр, `ё→е`, кавычки, повторные пробелы |
| `exact_page_rate` | доля страниц, где распознанный текст после нормализации **полностью** совпал с эталоном |
| `mean_confidence` | средняя уверенность распознанных слов в шкале 0…1 |
| `field_exact_rate` | доля значений полей, извлечённых **точно** — метрика, которую реально оценивает `evaluate.py` кейса |
| `pages_per_second` | фактическая скорость распознавания |

Две последние метрики добавлены намеренно: базовые `char_accuracy`/`exact_page_rate`
описывают распознавание, а `field_exact_rate` — то, что попадает в `results.json`.
Смешивать их нельзя: высокая точность полей достигается и при ошибках в
служебных строках.

## Эталон (ground truth)

`benchmarks/ground_truth.json` генерируется скриптом
`backend/scripts/make_ocr_ground_truth.py` из архива кейса:

* шаблонные строки (заголовок, служебные строки, подписи, подвал) — фактически
  напечатанный текст страницы, проверенный по изображениям;
* значения полей — из `reference_results.json` (файл читается **только** в контуре
  тестирования, как и в `evaluate.py`);
* даты хранятся в обоих допустимых написаниях (`01.09.2023` и «1 сентября 2023
  года») — бенчмарк засчитывает совпавшее, потому что по правилам кейса оба
  обязаны давать одно значение;
* строка подвала `Идентификатор образца: open-NNN` входит в эталон: она
  напечатана на странице, хотя и не является полем.

## Запуск

```bash
python -m backend.scripts.tasks ocr-quality            # пересобрать эталон и замерить
# или явно:
python -m backend.scripts.make_ocr_ground_truth --archive <архив> --output benchmarks/ground_truth.json
python -m backend.scripts.benchmark_ocr \
  --ground-truth benchmarks/ground_truth.json --root <архив> --output reports/ocr-benchmark.json
```

Отчёт: `reports/ocr-benchmark.json` — сводка плюс разбивка по каждой странице
(точность, уверенность, число ошибок, время, промахи по полям).

## Настройки OCR

Бенчмарк печатает фактические настройки (`oem`, `psm`, целевой размер длинной
стороны, включена ли бинаризация), поэтому отчёт всегда можно сопоставить с
конфигурацией `backend/app/config.py` (`OcrSettings`).

Выбор настроек сделан замером на этом же наборе (30 страниц). Важно: **рост
`char_accuracy` сам по себе не является улучшением** — конфигурация обязана ещё
сохранять подписи-якоря, по которым детектор отметок локализует зоны:

| Конфигурация | `char_accuracy` | «М.П.» найден | поля | синтетика |
|---|---|---|---|---|
| psm 6 + Otsu | 0.7753 | 20/30 | 1.000 | ok |
| **psm 6 без бинаризации (текущая)** | **0.8713** | 20/30 | 1.000 | ok |
| psm 4 без бинаризации | 0.9063 | 4/30 | 1.000 | ok |
| psm 3 без бинаризации | 0.9075 | 4/30 | 1.000 | ok |
| psm 11 / psm 12 без бинаризации | 0.9114 | — | 1.000 | теряет блок отметок |

Поэтому в тестах есть два независимых контура: бенчмарк качества распознавания
(`test_*` не нужен) и `backend/tests/test_signatures.py`, который падает, если
конфигурация перестаёт находить графические отметки. Меняя `psm` или бинаризацию,
запускайте оба:

```bash
python -m backend.scripts.tasks ocr-quality   # качество текста
python -m pytest backend/tests -q             # отметки, поля, контракт
python -m backend.scripts.tasks evaluate      # метрики кейса
```

## Замеренные значения

См. README проекта, раздел «Качество». Значения получены этой командой на
открытом наборе (30 страниц) и не переносятся автоматически на закрытый набор:
он содержит новые значения и пропуски при тех же трёх типах и тех же правилах.
