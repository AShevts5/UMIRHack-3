# Презентация: 10 слайдов

Тезисы для защиты. Все числа — фактические, из `reports/open-set.json` и
`reports/verify.json`.

---

## Слайд 1. Проблема

Сотрудник деканата вручную сверяет реквизиты студенческих документов: есть ли
все обязательные сведения, подпись, печать. Студент узнаёт о недостающем
элементе уже после визита.

Что делаем: локальный сервис, который читает документ, показывает его поля и
**предварительно** проверяет комплектность по конкретным пунктам Положения.

Что не делаем: не принимаем документ, не оформляем отпуск, перевод или зачёт
практики (пункт 1.3, 1.4 Положения).

## Слайд 2. Сценарий студента

Фото/скан PNG, JPG или одностраничный PDF → тип документа → вопрос на русском →
распознанный текст, карточка полей, статус проверки, ответ со ссылками.

Границы: если сведений нет в документе и в Положении, сервис прямо говорит об
этом и направляет в деканат.

## Слайд 3. Архитектура

```text
Scanner/фото → loader (лимиты, PDF→PNG) → OCR rus_umir+eng (слова + координаты)
   → parser (якоря подписей, даты, «не найдено»)
   → detect_marks (пиксельный анализ графики)
   → rules_engine (пункты 3.1-3.3 / 4.1-4.2 / 5.1-5.3)
   → question_engine (4 класса вопросов, синонимы, честный отказ)
   → results.json / API / UI
```

Один и тот же pipeline обслуживает веб-интерфейс и пакетный экспорт — метрики
считаются по тому же коду, что видит пользователь.

## Слайд 4. Демо: справка об обучении

`open-001`: 8 текстовых полей + 2 графические отметки, статус `document_ok`,
источники `rule:3.1`, `rule:3.2`, `rule:3.3`. Подсветка найденных зон на
изображении.

## Слайд 5. Демо: заявление на академический отпуск

`open-014`: `missing_fields = ["leave_reason"]`, источник `rule:4.1`, остальные
поля читаются. Вопрос про отсутствующее поле → `answerable=false`, `value=null`,
`sources=[]`.

## Слайд 6. Демо: справка о практике и графические отметки

`open-021` — подпись и печать найдены; `open-023` — печать есть, подписи нет;
`open-004` — подпись есть, печати нет. Надписи «Подпись»/«М.П.» сами по себе не
считаются отметкой: решение принимается по пикселям (пункт 2.3 Положения).

## Слайд 7. Честное отсутствие ответа

«Какова стоимость обучения за следующий семестр?» → «В документе и в Положении
нет информации для ответа на этот вопрос. Обратитесь в деканат.» `answerable=false`,
`sources=[]`. Пункты 3.5, 4.4, 5.5 не устанавливают эти условия.

## Слайд 8. Качество на открытом наборе

30 документов, 120 вопросов, `evaluate.py` организатора:

| Метрика | Значение |
|---|---|
| `format_valid` | true |
| `field_accuracy_macro` | 1.0 |
| `validation_exact_match` | 1.0 |
| `question_exact_match` | 1.0 |

Дополнительно: целостность при переименовании файлов и смене `document_id`
(280 полей, 120 ответов — совпадение), PNG ≡ PDF (30/30), автотип 30/30,
отметки 50/50, лимиты и ошибки — 6/6.
Честная оговорка: набор мал и синтетический, на закрытом наборе значения могут
быть ниже.

## Слайд 9. Бонусы и UX (только работающее)

1. Автоопределение типа документа — 30/30 на открытом наборе.
2. Подсветка найденного поля и зоны отметки на странице.
3. Новый тип документа через `document_types.yaml` без правки кода.

Сверх кейса (путеводитель по вузу, `docs/guide_features.md`): вход с 2FA/JWT и через
Яндекс ID, справка по факультетам с официальных сайтов, карта вузов, AI- и голосовой
помощник без внешних LLM, PWA и Capacitor. Кабинет сотрудника деканата не реализован.

## Слайд 10. Развитие и границы

Модульная архитектура: правила вынесены в конфиг и отдельный движок, поэтому
подключение Положения реального вуза возможно **после официальной загрузки и
согласования**.

Ближайшие шаги: многостраничные PDF, устойчивость к поворотам и теням, сравнение
нашего OCR с локальным PaddleOCR на расширенном корпусе, интеграция с настоящим
документооборотом деканата.
