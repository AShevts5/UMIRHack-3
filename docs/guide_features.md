# Путеводитель по вузу: фичи сверх кейса

Сверх обязательной части кейса «Онлайн-деканат» превращён в приложение-путеводитель:
вход в стиле РИНХ, «холл» с разделами, справка по факультетам, карта вузов, AI- и
голосовой помощник, PWA и мобильная сборка. Проверка документов (основной пайплайн
кейса) стала разделом «Обращение в деканат» и не изменилась: те же адреса
`/api/v1/*`, тот же `results.json`, те же метрики открытого набора.

| № | Фича | Где в коде |
|---|------|-----------|
| 1 | Регистрация, вход, 2FA (TOTP) и JWT | `backend/app/services/auth.py`, `frontend/src/screens/AuthScreen.tsx`, `Profile.tsx` |
| 2 | Вход через Яндекс ID (OAuth 2.0) | `backend/app/services/oauth_yandex.py`, `guide_api.py` |
| 3 | PWA: установка, офлайн-оболочка, иконки | `frontend/public/manifest.webmanifest`, `public/sw.js`, `src/lib/pwa.ts` |

## Сценарий

1. **Вход.** Слева мультяшный главный корпус РИНХ на Большой Садовой (ракурс с фото),
   справа окно входа в тёмном стиле: «Войти через Яндекс», логин или email, пароль,
   «Забыли пароль?», «Зарегистрироваться». На телефоне здание уходит наверх узкой
   полосой. Для демо есть «Продолжить без входа».
2. **Переход внутрь.** Камера приближается к дверям здания (Framer Motion, 0,9 с),
   проступает холл. Клик или Esc пропускают анимацию, при `prefers-reduced-motion`
   её нет совсем.
3. **Холл.** Фон — иллюстрация холла (пост охраны, турникеты, мраморная лестница),
   поверх разделы: «Обращение в деканат», «Факультеты и корпуса», «Карта вузов»,
   «История обращений». Картинки, заголовок и приветствие берутся из конфига вуза.
4. **AI-помощник** виден на всех экранах, начинает с фразы «Приветствую Повелителя
   своего! Чем могу быть полезен?», умеет отвечать голосом.

## Реестр вузов: новый вуз без кода

`backend/app/configs/universities/<id>.yaml` — название, логотип, координаты,
корпуса, картинки холла (`hall.building_image`, `hall.hall_image`), файл положения
(`regulation`), какие разделы доступны (`sections`), факультеты. Новый вуз — новый
YAML (и, при желании, картинки в `frontend/public/universities/<id>/`).

* **РГЭУ (РИНХ)** работает полностью. Проверка документов идёт по учебному Положению
  кейса (`regulation: case-rules`), это честно подписано в холле.
* **ЮФУ** — справка и карта; положения нет, поэтому «Обращение в деканат» помечено
  «скоро» (сервер сам переводит раздел в `soon`, если файла положения нет).

API: `GET /api/universities`, `GET /api/universities/{id}`; выбранный вуз хранится в
профиле (`PATCH /api/auth/me`) и в браузере.

## Данные факультетов: только с официальных сайтов

Собраны 11.10.2026 вручную с rsue.ru и sfedu.ru, у каждой записи есть `sources`.
Чего на сайте нет — оставлено пустым и в интерфейсе показано как «нет на сайте».
Противоречия сайта (например, разные номера кабинета на двух страницах) записаны в

* ЮФУ: 25 подразделений (20 в Ростове-на-Дону, 5 в Таганроге), 21 адрес; кабинеты и

Сверка с сайтами автоматизирована: `python -m backend.scripts.check_faculty_sources`

кабинет и фамилия руководителя (адреса, спрятанные sfedu.ru от спам-ботов, раскодирует

Перед защитой данные всё равно стоит проверить на месте: часы работы и этажи на сайтах
почти не указаны.

## Учётные записи

* Пароли — scrypt (стандартная библиотека), пользователи — SQLite в `var/`
  (`UMIR_DATA_DIR`). Токен доступа — JWT HS256 на 12 часов; секрет —
  `UMIR_JWT_SECRET` или сгенерированный файл `var/jwt_secret`.
* 2FA — TOTP по RFC 6238 (Яндекс Ключ, Google Authenticator): в профиле
  «Включить 2FA», QR-код рисуется локально (segno). После пароля сервер выдаёт
  короткий challenge, токен доступа — только после кода.
* «Забыли пароль?» — почтовый сервер не подключён, поэтому ссылка сброса пишется в
  журнал сервера (это сказано пользователю). Ссылка одноразовая.
* Защита от перебора: 8 неудачных попыток за 5 минут на логин.
* В профиле — «Сменить пароль» (нужен текущий) или «Задать пароль», если вход был
  только через Яндекс ID (`POST /api/auth/password/change`).
* Яндекс ID можно привязать к уже существующему аккаунту (профиль → «Привязать
  Яндекс ID») и отвязать, если у аккаунта есть пароль. Браузер при переходе на Яндекс
  не передаёт заголовок с токеном, поэтому профиль получает короткий (10 минут) токен
  привязки, он едет в httpOnly-cookie; один Яндекс ID нельзя привязать к двум аккаунтам.
* «Мои данные»: выгрузка профиля и истории одним JSON (`GET /api/me/export`, без хеша
  пароля и секрета 2FA), очистка истории (`DELETE /api/me/history`) и удаление аккаунта
  вместе с историей (`POST /api/auth/me/delete`, нужны пароль и код 2FA, если включена).
* Вуз можно выбрать прямо на экране входа (переключатель «Ваш вуз»): меняется
  иллюстрация корпуса и холл.
* Проверки документов от входа не зависят: жюри и пакетный режим работают как раньше.
  Вошедшему пользователю итог проверки (имя файла, тип, пропуски — без содержимого)
  пишется в «Историю обращений» (`GET /api/me/history`). Пропуски показаны названиями полей
  из `document_types.yaml`, есть фильтр «все / с пропусками / полные».

### Вход через Яндекс

1. Создать приложение на https://oauth.yandex.ru: платформа «Веб-сервисы»,
   Redirect URI `http://localhost:8000/api/auth/yandex/callback` (или ваш адрес),
   права «Доступ к логину, имени и фамилии» и «Доступ к адресу электронной почты».
2. Запустить сервер с ключами:

```bash
UMIR_YANDEX_CLIENT_ID=... UMIR_YANDEX_CLIENT_SECRET=... python -m backend.scripts.tasks api
# Docker:
docker run --rm -p 8000:8000 -e UMIR_YANDEX_CLIENT_ID=... -e UMIR_YANDEX_CLIENT_SECRET=... umir-dean
```

Если сервис доступен по другому адресу, задайте `UMIR_PUBLIC_URL`. Без ключей кнопка
честно говорит, что вход не настроен, и никуда не обращается.

## AI- и голосовой помощник без внешних LLM

Требование кейса — никаких внешних OCR/LLM API. Помощник не генерирует текст, а
находит ответ локально (`POST /api/assistant/ask`) в трёх источниках: справка о
приложении (`assistant_faq.yaml`), данные вузов (факультеты и корпуса) и пункты
Положения (`rules.md`). Если ничего не подошло, он прямо говорит, что не знает, и
предлагает темы — тот же принцип честного отказа, что и в ответах по документу.

Голос — Web Speech API браузера: озвучка (`speechSynthesis`) работает голосом
системы; распознавание включает `processLocally`, если браузер умеет распознавать на
устройстве (Chrome 139+), иначе используется встроенное распознавание браузера —
это подписано в виджете.

## PWA и мобильное приложение

* PWA: манифест, иконки, service worker. Без сети открываются оболочка, холл,
  справка по факультетам и список вузов (последние загруженные данные); проверка
  документов и вход требуют сервера. Тайлы карты OSM не кешируются (их правила).
* Android (Capacitor 7): `frontend/android/`. Сборка:

```bash
cd frontend
VITE_API_BASE=http://<адрес-сервера>:8000/api/v1 pnpm run build:mobile
pnpm exec cap open android      # Android Studio → Build APK
```

OCR и проверка остаются на сервере (ноутбук в той же сети), в приложении — интерфейс.
Вход через Яндекс внутри приложения открывает страницу сервера.

## Карта

Leaflet + react-leaflet, подложка OpenStreetMap (бесплатно, без ключа, подпись
«© OpenStreetMap»). Метки вузов с логотипами, всплывающая карточка «Перейти в вуз»,
поиск по названию, слой корпусов выбранного вуза; из справки по факультетам кнопка
«Показать на карте» открывает нужный корпус. Карта грузится отдельным чанком только
при открытии раздела.

**Геймификация «дойти до корпуса».** На карте кнопка «Где я?» ставит человечка по
геолокации браузера (или «Старт рядом с вузом» для демо без геолокации), показывает
три ближайших корпуса с расстоянием по прямой и примерным временем пешком. По кнопке
«Идти» человечек бежит к корпусу (при `prefers-reduced-motion` переносится сразу), а у
дверей предлагает «Войти в холл». Маршрут по улицам не строим — без внешних сервисов
это было бы выдумкой, поэтому честно пишем «по прямой».

**Значки.** За действия в путеводителе выдаются значки (вошли в холл, первая проверка,
документ без пропусков, справка по факультетам, добежали до корпуса, вопрос помощнику,
вопрос голосом, включили 2FA); при получении появляется плашка, все значки и подсказки
— в профиле. Хранятся только в браузере (`localStorage`), на сервер не отправляются.

**Офлайн.** Без сети сверху появляется плашка: что открыто из сохранённой копии, а
что заработает, когда связь вернётся.

## Доступность

* Диалог с помощником хранится в `sessionStorage`: при переходе между экранами он не
  теряется, после закрытия вкладки начинается заново.
* Помощник: Esc закрывает, фокус переходит в поле вопроса и после закрытия
  возвращается на кнопку помощника. В холле «Спросить на посту охраны» открывает
  помощника.
* Кнопка «К содержимому» для навигации с клавиатуры; при смене раздела меняется
  заголовок вкладки и фокус переходит на новое содержимое (экранный диктор читает
  новый раздел).
* Анимации выключаются при `prefers-reduced-motion`.
* Проверено axe-core (WCAG 2.1 A/AA) на 10 экранах в светлой и тёмной теме: вход,
  регистрация, холл, помощник, проверка и её результат, факультеты, карта, история,
  профиль — 0 нарушений (11.10.2026). Для этого затемнены второстепенные цвета текста
  светлой темы и подписаны метки на карте.
* Разделы (проверка документов, факультеты, карта, история, профиль) — отдельные чанки:
  стартовый код меньше примерно на 11 %, остальное догружается в фоне, когда браузер
  свободен, и service worker кладёт это в кеш для офлайна.

## Безопасность ответов сервера

* Заголовки `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: strict-origin-when-cross-origin` (тайлам OSM по их правилам нужен
  Referer с адресом сайта), `Permissions-Policy` (микрофон и геолокация только для самого
  приложения).
* Если токен истёк или аккаунт удалён, сервер отвечает 401 с
  `WWW-Authenticate: Bearer error="invalid_token"`; интерфейс по нему выходит из аккаунта
  и показывает «Сессия истекла, войдите ещё раз». Неверный пароль так не помечается.

## Мелкие пункты недельного плана (11.10.2026)

* **Демо-режим.** На стартовом экране «Обращения в деканат» кнопки «Пример 1–4»:
  полная справка об обучении, заявление на отпуск без подписи и даты заявления,
  справка о практике в PDF и «фото под углом» (поворот 13,6°, тень). Это вымышленные
  документы нашего генератора (`backend/scripts/make_demo_samples.py`), а не страницы
  открытого набора. Тест `test_demo_samples_give_the_promised_result` следит, что
  каждый пример даёт обещанный итог.
* **Загрузка.** Ctrl+V вставляет картинку из буфера; на телефоне есть кнопка
  «Сфотографировать документ» (`capture="environment"`).
* **Обработка.** Секундомер «Прошло N с», после ответа — «Готово за N с».
* **До и после.** Если предобработка поворачивала лист или выравнивала свет, в ответе
  `/api/v1/analyze` приходит `page_enhanced: true`, и над страницей появляется
  переключатель «После выравнивания / Исходник». Рамки полей рисуются только на
  выровненной странице: в её координатах их и считали.
* **Четвёртый тип через конфиг.** `examples/new-document-type/document_types.yaml`
  описывает «Справку с места работы» и подключает три типа кейса через `extends`
  (новый ключ загрузчика конфига). Положение кейса не меняется: пункты 7.1–7.3 есть
  только в копии `examples/new-document-type/rules.md` и помечены как демонстрация.
* **Коды восстановления 2FA.** При включении 2FA выдаются 10 одноразовых кодов вида
  `abcde-fghjk`; хранятся только SHA-256 хеши, в выгрузку данных не входят. Код
  подходит вместо кода из приложения при входе, при выключении 2FA и при удалении
  аккаунта. Новые коды — `POST /api/auth/2fa/recovery` (кнопка в профиле), старые при
  этом сгорают.
* **Демо-аккаунт для жюри.** `UMIR_DEMO_ACCOUNT=1` (или свой логин вместо `1`)
  добавляет на экран входа кнопку «Войти в демо-аккаунт для жюри». Вход без пароля,
  поэтому в этом аккаунте запрещены 2FA, пароль, привязка Яндекс ID и удаление
  (ответ 403). По умолчанию выключен, в том числе в Docker-образе и на сервере.
* **Веса OCR.** `python -m backend.scripts.tasks models` проверяет `rus`/`eng` по
  SHA-256 (tessdata_fast 4.1.0, на них получены метрики) и при нехватке скачивает их в
  `models/tessdata` — сервис ищет эту папку сам.
* **Telegram-бот.** `UMIR_TELEGRAM_TOKEN=… python -m backend.scripts.tasks bot`:
  фото или файл → тип, итог проверки по Положению, ответ на вопрос из подписи; потом
  можно задавать вопросы текстом. Bot API вызывается через `urllib`, новых
  зависимостей нет. Telegram — только канал доставки: распознавание локальное,
  документы не сохраняются, в памяти держится разбор последнего документа чата.

Тесты: `backend/tests/test_plan_extras.py`.

## Фирменный стиль «Академиум»

* Логотип лежит в `frontend/public/brand/`: `academium-logo.png` и `.webp` (целиком, с
  надписью), `academium-mark.webp` и `academium-mark-128.webp` (только знак, для входа и
  шапки). В шапке стоит знак, а название «Академиум» набрано текстом, чтобы читалось в
  обеих темах. Из того же знака нарезаны иконки сайта, PWA (`frontend/public/icons/`) и
  Android (`frontend/android/app/src/main/res/mipmap-*`, заставки `drawable*/splash.png`).
* Вход: тёмно-синий фон под цвет логотипа с цветными пятнами, каракули
  `brand/doodles.svg`, мерцающие искорки и бумажный самолётик (при «уменьшить движение»

  карточкой.
* Холл: новая светлая иллюстрация `universities/_default/hall.svg` (её же копия у РИНХ):
